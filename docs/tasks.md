# Tasks

Planned 2026-10-26. Architecture: [architecture.md](architecture.md). Decisions: [adr/](adr/). Each task is sized for one agent session (the `implementer` agent unless noted). **P** marks tasks that can run in parallel with their siblings (no shared files). Milestones are a sequence, not a schedule; there are no dates. M1–M4 are the critical path to the first public lock (ADR 0010); M5+ can interleave once M4 is done.

Conventions for every task: ruff clean, `uv run pytest -q` green, new modules get a module docstring, no parquet in git, and any job touching time boundaries adds a test.

## Sequence (decided 2026-10-27)

Work order, no dates. Each wave ends with a refit, a regrade, and a new `model_version`; live rows are never touched.

1. **Model identity before the first public record.** Feature groups (M2.8, ADR 0012), the availability family (M1.10), QB and strength extras (M1.11), schedule context (M1.12), backfill to 1999 (M1.17), then re-propose the three personas at the group level and review. Reason: the first lock should lock the personas we intend to keep.
2. **Live.** `nfl lock` (M4.1), weekly commands and runbook (M4.2), the container (M7.1, so the lock runs in the image from day one), a dry-run week, then public locks. The `/nfl-narrative` skill runs each week from the first dry run so the Narrative record starts accumulating.
3. **See it.** Streamlit v2 pages (M5.1–M5.6), the DIY matrix and page (M5.8–M5.9), weather at lock (M5.7). Local only, fast iteration against the real marts.
4. **The local LLM path (ADR 0014, 2026-10-28; was the API path).** Desktop setup by Austin (M6.1b, `docs/desktop-llm-setup.md`), the LLM client and call log (M6.1), the local research pipeline (M6.2L) compared against the skill's records (M6.2e), previews and faithfulness on the local model (M6.3), evals (M6.4), Narrative approach in shadow (M6.5). The Sonnet API job stays as a fallback if the comparison shows the local model is clearly worse.
5. **Host it** (plan in `docs/hosting.md`, ADR 0015): container (M7.1), GCP bootstrap + Terraform (M7.2), bucket data root (M7.3), cloud locks with a shadow week, public site-data bucket + React site on Firebase (M7.4–M7.5), alerts (M8.1), desktop upload path. Last on purpose: it packages marts and pages that are still changing in steps 3–4.
6. **Next feature wave.** FTN extras and matchup interactions (M1.13), participation ingest (M1.14), the coordinator table (M1.15), scheme priors (M1.16), the Matchup approach. Any wave can slot in after step 2 without blocking the others.

Steps 3, 4 and 5 touch different directories and can run as parallel implementer tracks once step 2 is done.
