# The public site (M7.4, M7.5; v2 layout M10)

Status: current, verified 2026-11-06 against `web/` after the site walk fixes (M13).

A static React app on Firebase Hosting that reads the published site JSON from the public bucket. Decisions: ADR 0009 (static site, no API), ADR 0015 (data from a public bucket, so data changes never need a deploy). The Streamlit app stays as the local explorer; this replaces it as the public face.

- **App:** `web/`, Vite + React 19 + TypeScript, React Router, TanStack Query (fetch + cache), zod (runtime contract checks), Tailwind 4 (layout), Recharts plus small hand-written SVG charts (dot-and-whisker, dumbbell, diverging bars) on `d3-scale`. Vitest + Testing Library.
- **Data:** `VITE_DATA_URL` (default `https://storage.googleapis.com/nfl-project-prod-site`). Pages fetch `site/meta.json`, `site/slate_<season>_<ww>.json`, `site/game/<id>.json`, `site/tracker.json`, `site/hypotheses.json`, `site/coaches.json`, `site/diy_matrix.json`, `site/season_<yyyy>.json`, `site/audit.json`, and lock artifacts under `predictions/`. In `npm run dev`, a small Vite plugin serves the local `data/marts/site` at the same paths, so the app runs against your laptop's data with no bucket.
- **Contract:** TypeScript types and zod schemas in `web/src/data/contract.ts` mirror `src/nfl/site.py`. A test parses every real JSON file under `data/marts/site` (skipped when absent) and checked-in fixtures (always), so a contract change in Python that breaks the site fails CI.
- **Build-your-own in the browser:** the evaluator (walk-forward Platt, metrics, buckets, season view, fit-toward-you ridge) is ported to TypeScript in `web/src/diy/`. A parity test compares it with Python's `nfl.approaches.diy.evaluate` on fixed weight sets (fixtures generated by `scripts/web_fixtures.py`).
- **Contract: `league.json`** (ADR 0019, schema "1", `LeagueFile` in `nfl/league/build.py`): `season`, `as_of`, `through_week`, `n_sims`, `seed`, `shock_sigma`, `tiebreak`; `teams[]` standings rows with `seed_today` and `div_rank`; `odds.student` and `odds.market`, each `{sources, teams{code: {playoffs, division, bye, seed[7], rounds{div, conf, sb, champ}, wins{mean, lo, hi}}}}`; `games[]`, every remaining game by leverage, with `p_student`, `p_market`, `market_source`, `swings[]` from the Student's runs and `n_home_wins`, `n_away_wins`; `history{code}` from the Tuesday snapshots; `similar{code}`: `games_played`, `k_summary`, `made_playoffs`, `rounds`, and `neighbours[]` (the 10 nearest: `season`, `team` as printed then, `dist`, `rec_then`, `final`, `playoffs`, `round`); a team under four games played has no entry. Written last in `site.build`, in its own try/except. `through_week` is the last week with every game final. A rebuild with no new data is identical apart from the timestamps. Results arrive by the 07:00 retro ingest, so a game can sit in `games[]` after it ends: the page keeps only games with a kickoff still ahead. After the last regular-season game the file keeps the final standings with no odds or games.
- **Contract: `teams.json`** (ADR 0019, schema "1"): `season`, `week` (the next week to be played), `as_of` (the feature build time), `features[]` in registry order (`id`, `label`, `short`, `description`, `unit`, `group`, `group_name`, `better` higher, lower or null for no good or bad, `n`, `mean`, `lo`, `q1`, `med`, `q3`, `hi`), and `teams{code}` (`conference`, `division`, the record, `through_week`, `games[]`, `values{}`, `pct{}`, `rank{}`). Values are each team's row for its next game as of the last feature build, so they change with the features and not when a game kicks off; the record stops at the same point. A missing value is an absent key. A 404 shows an empty card, because the file is published by data jobs and the page deploys on its own.
- **Deploy (M7.5):** `scripts/firebase_deploy.py` uses the Firebase Hosting REST API (create version with config, populate file hashes, upload gzipped files, finalize, release) with a token from `gcloud auth print-access-token`. That's keyless in Actions (Workload Identity, the existing `nfl-deploy` service account has `firebasehosting.admin`) and works locally with your gcloud login. Chosen over the Firebase CLI because current CLI releases have open reports of ignoring Workload Identity credentials in CI, and the official deploy action still needs a stored key. Hosting config sent with each version: SPA rewrite to `/index.html`; `Cache-Control: public, max-age=31536000, immutable` for hashed `/assets/**`, `no-cache` for HTML; a CSP that allows fetches only from self and `storage.googleapis.com`.
- **Workflow:** `.github/workflows/site.yml`, called by `ci.yml` after both test jobs pass on a push to `main` touching `web/**` (and manual dispatch): `npm ci`, typecheck, lint, test, build, deploy. `ci.yml` gains a web job (typecheck, test, build) for pull requests.

## v2: one answer first (ADR 0017, M10)

Decided 2026-11-03 after the retrospective made the game page 21 sections long. Every page opens with a summary strip (3–5 tiles, each one statement, linking to the tab that explains it) and keeps its detail behind URL-synced tabs (`?tab=`). Sections keep their content and lose their duplicate explanations (one lede sentence, help on hover, one fine-print block per page). Values are drawn on a league band (p10–p90 of team season-to-date values) with the number printed at the row end. The slate becomes matchup cards with a compact approaches-vs-market strip (`?view=table` keeps the grid). Team colors appeared as a thin accent bar only (replaced by the ADR's amendment, below). Shared pieces: `Tabs`, `SummaryStrip`/`Tile`, `FinePrint`, `RangeRow`, `ProbStrip`, `TeamAccent`.

| Route | Summary strip | Tabs (`?tab=`) |
|---|---|---|
| `/`, `/week/:season/:week` | week recap: best approach, vs the market, picks right, biggest upset, luckiest team (finished weeks) | none; cards sort by `?sort=kickoff\|disagreement\|upset` (`disagreement` is labeled Student vs market), `?view=table` for the grid |
| `/game/:id` | pregame: the pick, vs the market, biggest factor, key absence or biggest edge; finished: result, approaches right, played like, swing plays, biggest surprise | `retro` (finished games with a retro; default), `preview` (default otherwise), `approaches`, `tendencies`, `details`, `news` |
| `/tracker` | the Student vs the market, live games graded, best approach, calibration, paper bets | `season`, `backtest` (also log loss by season and disagreements, which span every season), `calibration`, `bets` |
| `/hypotheses` | none | `time` (default; `?item=` picks the feature), `effects` |
| `/method` | none | `how`, `limits`, `data` |

The Student is the headline line (`HEADLINE` in `lib/models.ts`; D5): the pick, the slate's status, the recap's picks right and the tracker's tiles read it. The ensemble is a diagnostic: `data/hideEnsemble.ts` strips it from every file at load, so pages never see it, and it is a no-op once the data has none. The game page is built around the game (round 2): `preview` is approach-free, one bar per group sized by the Global fit, with an approach picker that outlines that approach's reading on the same rows. The name "Global" never appears there. Groups come from `meta.groups`, and a group in neither the fit nor the overlay is no row; `isContextOnly` in `lib/meta.ts` keeps `coaching`, `off_scheme`, `def_scheme` and `matchups` out of the bars, the edges and the Biggest edge tile, reading `context_only` from meta plus a fallback set to delete once that field ships. `details` draws both teams on the league's band (`MatchupBand`, `meta.feature_bands`): faint from p10 to p90, solid over the middle half, a tick at the median. Further right is better, and a gap wider than the league's middle half stands out while the rest are muted. A push toward a team is always a plus (`ptsFor`, `ptsSide`): the side says whose it is. The overlay's outline is one neutral ink, since color on those bars means a team. `useChartTip` is the hover card on `MatchupBand`, `DivergingBars`, `Dumbbell` and `RangeRow`, on hover and keyboard focus.

Color (ADR 0017 amendment): on a game page and a slate card, `[data-matchup]` with `matchupVars(away, home)` sets `--team-away` and `--team-home` for the theme, so use those and never a raw brand color. The League scatter uses the same slots for one team: `teamDotVars(code)` puts the main color in `--team-home` (the fill) and the second brand color in `--team-away` (the ring), because one color can't separate 32 teams. `lib/teamColors.ts` fits the brand colors and picks the pair; `teamColors.test.ts` holds all 992 matchups to contrast and colorblind floors. `--div-pos` and `--div-neg` stay for better and worse, helped and hurt.

The retro leads with the game too: tiles run result, played like, swing plays, biggest surprise, approaches right, and headlines don't mention approaches. Played like shows what goes into it: EPA per play decides it, success rate is context (`expectations.py` says why). Phase by phase is the wider view: who won passing, rushing, explosive plays, third downs, the red zone, special teams, field position and turnovers. It's description, not a score, and none of it feeds the verdict; each row comes from `phases` in the record, computed by `_phases` in `retro/game.py`. Swing plays are one bar per factor, home's swing minus away's, split into Variance and Pure luck by `partly_skill` on one shared scale. Global isn't shown in the retro or the recap table.

The retro's first chart is **How it unfolded** (`WpChart`, ADR 0020): `wp_series` from nflfastR's spread-adjusted win probability, home at the top, each team's area in its color, numbered turning points in time order, and the same plays in a "Turning points" list so nothing is hover-only. A point is the value after the play snapped at `t`, so a mark sits on the line. The lede and the ring name the winner's low only when it came after kickoff and was under 25%: an underdog that only rose never "fell" there. A swing is the difference of the two rounded percents, so a row's arithmetic holds. "Swing plays" stays the luck section; the two names are not interchangeable.

`PossessionStrip` sits under the curve on the same time axis (`timeScale` in `charts/wpScale.ts`, which both charts read, so a drive can't drift from its stretch of the curve): a segment per drive running to the next drive's start, a line at each score. **Drive by drive** (`DriveField`) is one row per drive on a field with the away team's goal on the left, so the away team drives right and the home team left, whichever ends they really used. Bars use `drive_start_yard_line`, and a touchdown runs to the goal line because `drive_end_yard_line` is the last snap. The strip's segments take hover and tap but no tab stop; `DriveField`'s rows carry the same drives for the keyboard.

A finished game keeps its result on screen: `Condensed` in `SummaryStrip.tsx` watches the full strip with an IntersectionObserver and, once it has left through the top, shows one line under the site header (`PinnedResult`: the score, OT, the result tile's verdict). The header's height is measured, not assumed. The shell has no height, so nothing moves when it appears, and it's hidden from screen readers because the page header says the same. Tabs' `scroll-mt-32` leaves room for it when a tile scrolls a panel in. Pregame pages have no result to pin.

Slate cards lead with the game too: teams, the line and total, a **why this game** line, a tendencies contrast when it's stark, then the approaches strip. `whyLine` and `contrastLine` in `slate/helpers.ts` build them from the row's `card` block (`_card` in `site.py`). Everything in that line is a public claim, so the rules are strict:

- **Quarterbacks.** Neither the schedule's name for an unplayed game nor the depth chart is reliable alone, so the card needs both, for the current week only, before kickoff. It says "listed to start" when they agree and "starter unclear" naming both when they don't. A hurt player drops out of the comparison. "Usually" needs three starts and a clear lead, and a QB who started the team's last game isn't news.
- **Absences.** Only a player listed first at a position on the chart for that game (special teams excluded, matched by player id), and not Out or Doubtful at the team's last game.
- **Edges.** `countsAsEdge` in `lib/meta.ts`: not context groups, not Venue & weather (it only shifts home advantage), and not Rest & travel on a neutral site, where it favors the nominal away team. The Preview keeps their bars and drops their labels. On a neutral site the Preview moves the neutral-site discount onto the Home field row, which can go negative, and an approach without that feature (the Sharp) keeps its full value; the Approaches tab shows the raw pieces.
- **Card contract.** A bad `card` costs that game its line, with a console warning, not the week its slate. `contract.test.ts` validates cards and the injury flags, so wrong types and a dropped flag fail there.

The tracker's season chart plots each line's gap to the market (market cumulative log loss minus the line's, so above zero is ahead), with a band at ±0.025 for gaps too close to call: `GAP_BAND`, the 90% range of a gap over 120 games, which narrows as games accumulate. References (`REFERENCES` in `lib/models.ts`) draw as a dashed ring in `Swatch`, so in tables and toggles, and `ModelBadge`'s `reference` prop adds a tag in tables. A list built from a data file filters with `isPublicLine`, so diagnostics never appear because the file carries them. The week recap's Full recap names the week's best call and costliest miss, from `best_call` and `costliest_call`.

Tile values are pure functions of the site JSON (`pages/*/summary.ts`, `slate/recapTiles.ts`), unit-tested. Within 5 points of even, results and played-like are called a toss-up, and on the tracker, log-loss gaps under 0.025 are "about the same" (`GAP_BAND`; a week's recap tile uses 0.005 and only describes that week).

## The design language (decided 2026-11-03, ADR 0017; the rules every page follows)

Why: with the retrospective added, a finished game's page was 21 stacked sections, each with a paragraph, hover help, a chart and a table; the slate was a 10-column table; charts auto-scaled so a small gap could fill a row and nothing said whether a value was good. Three flows were weighed (tabs plus a summary strip; a guided one-frame-at-a-time story; a dashboard of tiles with drill-down panels) and the first won: every section reachable in one click and shareable by URL, with the story's discipline inside each tab.

1. **One answer first.** Every page opens with a summary strip of up to five tiles. A tile is a statement (an upset or not, how many approaches were right, the biggest surprise), never a restated number; its sub-line is six words; it links to the tab that explains it. Tile values are pure functions of the site JSON in `pages/*/summary.ts` and `slate/recapTiles.ts`, unit-tested.
2. **Detail behind URL-synced tabs** (`?tab=`, history replaced, not pushed). A finished game opens on its retro; a pregame game on its forecast.
3. **Text budget.** One lede sentence per section (what you're looking at, not how to read it); help on hover for the method; caveats in one `FinePrint` per tab or page, not per section; a legend once per chart kind.
4. **Every number gets a frame.** A value sits on the league's p10–p90 band for that metric (`RangeRow`), with the average as a tick and the value printed at the row end; nothing requires hover. For the retro's efficiency rows the band is the 32 teams' season-to-date values (`league_lo`/`league_hi`, additive contract fields, null when fewer than 8 teams; the chart falls back to auto-scale when missing).
5. **Visual before table.** Tables live behind "show the numbers"; the injury report is the one table-first section.
6. **Status and meta are quiet.** Kickoff, stadium, QBs and lock status are one muted line under the title; the final score is the only loud element.
7. **Team identity without logos** (ADR 0011): a thin team-color bar (`TeamAccent`, from nflverse `teams`, with a ring for dark colors) under each code; approach colors stay the chart colors.
8. **Calls are honest about noise.** Within 5 points of even a result or a played-like is a toss-up; on the tracker, log-loss gaps under 0.025 are "about the same" (`GAP_BAND`; a week's recap tile uses 0.005 and only describes that week); a line older than 3 days says so ("line from Oct 27").
9. **Slate as matchup cards** on every screen size, one computed sentence each, sorted by `?sort=`; `?view=table` keeps the grid for power users.
10. **Phone first for the slate and the game page**; the tracker and build-your-own may lean desktop.
11. **Motion is information, and it is CSS** (ADR 0020). Animate only to show a direction or an order (a curve drawing in time, a dot sliding from the market to its value, bars growing from the axis, the panel a tile sent you to). Every animation reads the `--dur-*` and `--ease-*` tokens in `index.css`; `prefers-reduced-motion` zeroes them; elements render in their final state and animate from an offset back to it. No count-ups, no animation library, Recharts stays static. Loading shows the page's shape (`Skeleton`), not a word.

Motion classes live at the end of `index.css`: `wp-line`, `wp-mark`, `dot-slide` (reads `--from-x`), `bar-grow` (reads `--i`, capped at 7), `chart-tip-in`, `tab-panel-in`, `tile-flash`. `index.css.test.ts` fails on a literal time in any animation. jsdom runs no CSS, so check motion in a browser. A tile's scroll and flash run from `showPanel` in `SummaryStrip.tsx`, which retries because the router applies a tab change as a transition; tab changes pass `preventScrollReset`, or `ScrollRestoration` would cancel the scroll. Skeletons are for the game page, slate and tracker (`Loaded`'s `shape`); pages with no fixed shape keep the words `Loading …`. `useChartTip` opens on hover, focus, tap and click, and closes on a pointerdown outside, for iOS Safari. `ProbStrip`'s compact form keeps `<title>`: it sits inside a link, and a tip there would add dozens of tab stops. `DotWhisker` takes `focusable={false}` for a long list whose text is repeated below it.

Kit: `Tabs`, `SummaryStrip`/`Tile`, `FinePrint`, `TeamAccent`, `RangeRow`, `MatchupBand`, `useChartTip`, `ProbStrip`, and from M14/M15 `Scatter`, `WpChart`, `PossessionStrip`, `Skeleton` (in `web/src/components/` and `web/src/charts/`), colors from CSS tokens. Still open: the tendencies dumbbells on the same league band (hub decision D2).
