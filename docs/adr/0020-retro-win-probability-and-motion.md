# ADR 0020: The retro's win-probability chart, turning points, and a motion policy

Status: accepted 2026-11-05 (Austin). Research: `.notes/plans/pop-wp-chart-motion.md` (uncommitted; numbers below were measured there on the 121 live retros of 2026-11-05). Tasks: M15. Amends ADR 0016 (retro contract) and adds a rule to ADR 0017.

## Context
The retro is the best idea on the site and reads as text and tables. nflfastR's win probability is already in the play-by-play, so every finished game can carry a curve of how it unfolded, and the retro's "swing plays" can be pointed at on it. Separately, nothing on the site moves: no transitions, no loading shapes, and two charts still use `<title>` tooltips that do nothing on touch. Austin wants the site to feel alive without decoration.

Facts that shaped this: `curated/plays` keeps `wp` but drops `wpa`, `home_wp`, `vegas_home_wp`, `vegas_home_wpa` and the `fixed_drive*` columns; the raw snapshot has them all, back to 1999. The retro's "swing plays" are per-team luck totals (fumbles, 3rd and 4th downs, kicks, penalties) with no play ids. A game has about 175 plays; after dropping repeats, 152 points. The game page's JavaScript is 11.7 KB gzipped and loads no chart library (its charts are hand-rolled SVG on `d3-scale`).

## Options
1. **Which win probability.** (a) `home_wp`, game state only: favorites start near 50%, which contradicts the forecast tab on the same page; its first value is 13.9 points from the site's market on average. (b) `vegas_home_wp`, nflfastR's model with the pregame spread, whose weight decays to under 2% by the final gun: it starts 1.9 points from the site's market on average (max 6.3), and has the better log loss in nflfastR's own write-up. The chart is descriptive and feeds no approach, so ADR 0013's no-market-input rule does not apply.
2. **Marked plays.** (a) Try to map the luck totals back to plays. (b) Pick the chart's own plays: the top five real plays by |wpa| (at least 5 points), tagged with the luck factor they are counted in where one applies (66% of them are). (a) has no data to map with.
3. **Motion stack.** (a) The `motion` package: 29–59 KB gzipped, two to five times the game page's JavaScript, for springs and gestures this site does not need. (b) CSS keyframes and transitions through tokens: 0 KB, and jsdom ignores CSS animation so tests see the final state. (c) The View Transitions API for route crossfades only, already in React Router's typings and in 93% of browsers.
4. **Drives.** (a) A possession strip under the curve on the same time axis. (b) A field diagram with one bar per drive. (c) Both, strip first.
5. **Story layout.** A reordered retro with a pinned mini summary strip, or the scroll-driven story ADR 0017 rejected.

## Decision
- **Curate seven more play columns**: `vegas_home_wp`, `vegas_home_wpa`, `fixed_drive`, `fixed_drive_result`, `drive_start_yard_line`, `drive_end_yard_line`, `drive_play_count`. One hash change, one rebuild of every retro. The retro's `_load_plays` reads its own season's partition, not the all-season glob, because DuckDB fails to bind a column that older partitions lack.
- **The retro contract gains `wp_series` and `drives`**, additive and nullable (ADR 0015), with `SCHEMA_VERSION` bumped so the daily job rebuilds every retro. `wp_series` holds the spread-adjusted home win probability at each play where it changed, as `[t, p]` pairs on elapsed game seconds (overtime continues past 3600, 600 s a period in the regular season and 900 in the playoffs), the end time, up to five **turning points** (real plays only: pass, run, punt, field goal, extra point, kickoff; never kneels or no-plays), the winner's lowest point for a comeback sentence, and the model name. Each turning point carries the home probability before and after, the offense, the quarter and clock, nflverse's play text trimmed to 160 characters, and the luck factor it is counted in when one applies. About 1.8 KB gzipped per retro.
- **The chart** is hand-rolled SVG in the existing kit: time on x with quarter rules, home win probability on y with each team's name at its own 100% end, the area between the line and 50% filled in that team's color (ADR 0017 amendment: color means the team), numbered turning points with the `useChartTip` card, and the same plays listed as text under the chart so nothing is hover-only. It sits first on the retro tab, under the headlines. The names are fixed: **"Turning points"** for the chart's plays, "Swing plays" stays the luck section.
- **Motion is information, and it is CSS.** Tokens `--dur-fast`, `--dur-base`, `--dur-slow`, `--dur-draw`, `--ease-out`, `--ease-in-out`, `--stagger` in `index.css`; `prefers-reduced-motion: reduce` sets every duration to zero and disables view transitions. Every animated element renders in its final state and animates from an offset back to it, so a page with no CSS or no motion is complete. Motion is used only where it shows a direction or an order: the curve draws left to right, strip dots slide from the market to their value, bars grow from the axis with a capped stagger, a tile's target panel flashes once when it scrolls into view, tab panels fade. No count-ups: tiles are verdicts, not numbers (ADR 0017 rule 1). Recharts stays static. No animation library; route crossfades through View Transitions are optional and last.
- **Loading shapes replace "Loading"** on the game page, slate and tracker: skeletons shaped like the strip, tab bar and two blocks, pulsing only under `motion-safe:`.
- **Touch tips everywhere**: `ProbStrip` and `DotWhisker` move from `<title>` to `useChartTip`.
- **Drives, phase 2**: the possession strip first (same data, same axis), then the field chart (end zones tinted by team, one bar per drive from start to end yard line, an end glyph per result, no logos). Kickoff rows carry `yardline_100` 35, so drives use `drive_start_yard_line`; the END GAME pseudo-drive is dropped.
- **The story layout, phase 3**, is a reordered retro with a pinned one-line summary strip, and it needs an amendment to ADR 0017 before it is built. The scroll-driven story stays rejected.

## Consequences
- The retro says, in its fine print, that win probability is nflfastR's model with the pregame spread, not this site's approaches, and that its quirks (the step at the end of a tied regulation, blowouts flattening at 99.9%) are the model's.
- The job code change (curate and retro) merges outside lock windows, and `nfl-retro` is run by hand after the image builds rather than waiting for 07:00. Retros are derived, so the rebuild is safe; about 121 games now, 285 by season's end.
- Play text is nflverse's (CC-BY, ADR 0011), five plays a game, trimmed and attributed. A template from fields exists as a fallback if that ever needs to change.
- `docs/site.md` gains the motion rule as rule 11; every later animation reads the tokens or it is a bug.
- Open: whether the comeback sentence becomes a sixth summary tile (ADR 0017 caps the strip at five), and whether orientation motion (route crossfades) is wanted at all.
