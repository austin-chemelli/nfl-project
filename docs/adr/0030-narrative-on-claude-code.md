# ADR 0030: Narrative research runs on headless Claude Code on Austin's Max login, on the desktop

Status: accepted 2026-11-18 for the direction (Austin: "use an approach that uses my claude max subscription instead of that setup ... still run on the desktop ... on a scheduled basis"); details decided 2026-11-19 (D35-D38: the Max login; fail and email; switch for Week 11 with a catch-up pass; the switch only, additions evaluated afterwards). Supersedes the LLM-provider parts of ADR 0007 (no Claude Max or OAuth tokens in the app) and ADR 0014 with its 2026-10-29 amendment (desktop open-weight model only) for narrative research. ADR 0014's other rules stand: no paid LLM API, no API fallback, failures email.

## Context
The desktop's 9B model (ADR 0014) took about 15 minutes a game, 3.5 hours a pass, and on 2026-11-18 froze the desktop badly enough that Austin stopped the Week 11 Wednesday pass. Its records were the weak part of the site: on the 56 records of Weeks 8 to 10 the roster check below would drop 87 items naming a player on the wrong team (mostly players traded before the Week 10 deadline: Cousins kept on LV, Downs and Allen on IND, Brissett on ARI) and 21 records that neither team had ("5-2-1" for 5-3-1). Most of its design existed only because the model was small: thinking off, fact ids instead of URLs, six small jobs per game, fixed query templates with one search pass, and a search stack (RSS feeds, Tavily, SearXNG) to work around a home IP being blocked.

Austin uses Claude Code on a Max plan, and job-search already runs `claude -p` headless from a systemd timer on the same desktop (its ADR 0015). The narrative ratings matter beyond text: `qb_status`, `injury_impact`, `motivation`, `revenge`, `lookahead`, `weather_concern`, `coaching_turmoil`, `sentiment`, `hype` and the Sharp's `public_bet_pct_home` enter every public line live at their group's mean fitted magnitude (ADR 0012 amendment).

**Anthropic's terms, read 2026-11-18.** Claude Code's Legal and compliance page: subscription OAuth "is designed to support ordinary use of Claude Code", and nothing prevents "an end user from signing in to the unmodified Claude Code binary with their own Claude subscription"; "Developers building products or services that interact with Claude's capabilities ... should use API key authentication"; "Advertised usage limits ... assume ordinary, individual usage of Claude Code and the Agent SDK". The support article on using the Agent SDK with a Claude plan (updated 2026-10-07) says `claude -p` on a plan login draws from the plan's usage limits (the June 2026 plan to move it to a separate credit pool was paused). This use is one person running the unmodified CLI on his own machine for his own project, no one else reaches Claude through it and nothing is resold; the part the terms don't address directly is that the output is published on a public site.

## Options
1. **Claude Code headless on the Max login, on the desktop** (chosen): the model searches, follows leads and writes the record; code checks it. No new service, no bill; shares Austin's plan limits; the login must be renewed by hand (it reported 18 days left on the laptop).
2. **The Max plan's included API credits ($100 a month) with a Console key**: the documented path for products, separate from Austin's limits; an API key in a script, which ADR 0007's line was written against. Not chosen (Austin, D35); it stays the known way out if Anthropic objects to a subscription login here.
3. **Keep the local model and improve it** (M6.6 follow-up searches, a bigger GPU, D11): free, but the model is the limit and the desktop can't run it without freezing.

## Decision
- **Producer `claude_max`, prompt `claude_v1`** (`src/nfl/llm/claude_research.py`, `nfl narrative claude`). One `claude -p --model sonnet` session per game, three games at a time, in a temporary folder outside any checkout so no CLAUDE.md, hooks, skills or connectors load (`--setting-sources ""`, `--strict-mcp-config`). Tools: WebSearch, WebFetch, and Read/Write/Edit inside the folder only (`--tools`, `--permission-mode dontAsk`, a generated settings file that also denies `~/.claude`, `~/.ssh`, `~/.config`, `~/dev` and `.env` files). The folder holds the game, both coaches and both teams' weekly rosters.
- **No credential handling in the app.** `claude` is an external program on its own login. Every API-key variable is removed from its environment; the pass refuses unless `claude auth status` reports a claude.ai login, and logs a WARNING (email) when the login expires within 3 days. No API key, no paid API, no fallback to one.
- **Code decides what is stored** (`src/nfl/llm/checks.py`): every cited URL must be a page opened in the session (from the stream-json transcript); code reads each cited page itself and its date replaces the model's; items citing a page outside the window drop; a player named under a team must be on that team's latest weekly roster (absences, injury notes, the QB) or at least on one of the two teams (everything else); a season record in text must be one either team had; no betting line in text. Numbers and names not found on the cited page are flagged and counted but not dropped yet (on the first records most misses were the check's own). Then the `GameNarrative` validator, with one repair turn in the same session on a schema error, and `ingest` with the ingest clock as `known_as_of`.
- **Run log:** one row per game session in `marts/llm_calls.parquet` (job `research_claude`: minutes, turns, tokens, searches, pages, items dropped, API-equivalent dollars as a gauge of plan use; nothing is billed). The session folder (prompt, transcript, raw and checked record, drops) is kept under `raw/narrative_claude/`.
- **Schedule:** `nfl-narrative.timer`, a systemd user unit in the desktop's WSL, Wednesday 18:00 and Saturday 07:00 Eastern, `Persistent=true`, running `scripts/desktop-narrative.sh` with `NARRATIVE_PRODUCER=claude` (same upload, `nfl-site` start and `nfl-desktop-narrative` log as before, so `nfl status`, the alert and `nfl-narrative-check` work unchanged). `scripts/desktop-setup.sh` checks and installs it; `--enable` turns the timer on and the old Windows task off, `--disable` reverses it.
- **When the login is out or the plan's limit is hit:** the game fails and the pass emails, as today (D36; no fallback to the local model, which froze the desktop on 2026-11-18). The cloud check before each lock still emails if games are missing.
- **The switch lands in Week 11** (D37): nothing changes until `desktop-setup.sh --enable` on the desktop; then one catch-up pass for every game not yet kicked off, published as soon as it finishes even though it is off schedule, and the timer from then on. The first lock that uses `claude_max` records is noted in the journal. Locks keep their `model_version`: the producer is an input change, recorded here and visible in the feature rows' version (`claude_v1`).

## Consequences
- A pass takes about 15 minutes instead of 3.5 hours, and the desktop does nothing heavy (the work is Anthropic's; WebFetch summaries come from a small model on Anthropic's side).
- Plan use: about $0.6 a game API-equivalent on Sonnet (3 games measured), about $15 a week for two passes, against a plan Austin also uses for his own work. Watch `/usage` after the first week.
- A Claude login lasts weeks, not forever: Austin renews it on the desktop when the warning email comes.
- If Anthropic objects to a subscription login here, option 2 is the switch; if the Max plan goes, the producer goes with it and the local pipeline (kept in the repo, `producer: local`) is the way back.
- M6.6 and M6.7 (D3) are superseded. The local stack (Ollama, SearXNG, Tavily) can be retired once Claude has run a few weeks; that is a separate change.
- The roster and standings checks can serve the local pipeline too if it comes back.
